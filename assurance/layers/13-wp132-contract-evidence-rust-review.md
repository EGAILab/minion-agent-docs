## Queue protocol and Rust determinism

The normal-case protocol is independently implementable: begin/poll each call in source order, drive runnable futures plus outstanding real provider I/O to quiescence, track held provider gates, release/abort one scripted step, repeat, and fail unresolved calls after the final step. A counted scheduler/waker plus provider-operation tracking can establish quiescence without fixed sleeps; an OS I/O wait is not quiescence while that operation can still complete. The runner must not implement FIFO, key linking, abort settlement, or tool logic itself.

Audited all 11 queue scenarios:

- same-target registration and FIFO: gated earlier key/body; later key lookup/body orders follow the production registration/tail links; the B-write gate also forces `result A` before B's write completion;
- different keys and different provider identities: A's held write plus quiescence forces B's completion before release;
- failed registration: gated canonical failure forces later registration to wait, then proceed; C's settlement rejects a lingering entry;
- error/abort release: in-flight A gate forces release order, but the pre-aborted B `canonical_path` assertion is invalid through Layer 06 (R004);
- abort-held-lock: A's write gate remains held after abort, forcing B to wait;
- symlink/target and not_found/not_directory keys: held earlier body forces the shared-key ordering; occurrence 2 distinguishes fallback absolute-path from in-lock absolute-path;
- edit/write sharing: A's read gate forces B's write to wait for A's entire production critical section.

No additional scheduler-luck assertion was found. Native-await implementation differences need not emulate JavaScript microtask counts. Uniqueness/native-whitespace/Unicode/diff mutants have killing corpus inputs; nonserialized registration, provider-unscoped queue, abort-listener release and two-probe access have discriminating provider-call/gate expectations. Binding-level controls still must be executed against each future implementation, not claimed as already run.

The explicit lone-surrogate exception is correctly recorded as a Layer-02/05 decoding hazard rather than a passing tool case. Rust typed Strings/serde boundaries must prove rejection before execute where that domain cannot be carried. R005 is a **different**, currently undisclosed entry-domain conflict.

## Blocking findings

### L13-WP132-R004 — tool-local pre-abort evidence contradicts required Layer-06 entry

- **Taxonomy/severity:** `CONTRACT_ASSURANCE_DEFECT`, blocking.
- **Affected:** schema top-level runner mandate and `case.signal`; write/edit cancellation scenarios; `builtin-mutation-queue-released-after-error-and-after-abort.yaml`; spec WP-13.2 cancellation/evidence entry description.
- **Pi reproduction:** direct write/edit `execute` registers before its first signal check. Pi's `agent-loop.ts::prepareToolCall`, however, checks abort after validation/before-hook and returns an immediate outcome **without invoking execute**. Both certified Minion implementations preserve that Layer-06 boundary.
- **Concrete contradiction:** `pre-aborted-existing` expects `fs_calls = ["canonical_path f.txt"]`; the schema demands the real Layer-06 pipeline with that pre-aborted signal. Python `_preflight` lines 489-497 returns immediately; Rust `tools/execution.rs` lines 885 onward does likewise. The queue scenario even requires pre-aborted B's canonical lookup before `result A`.
- **Fresh executable witness:** registered a signal-capable dummy tool named `write` whose execute records one call; invoked real Python `execute_call` with valid path/content and an already-aborted `RunAbortController.signal`. Observed `is_error=true`, text `Operation aborted`, **execute invocation log `[]`**. The candidate source was explicitly first on `sys.path`, not silently replaced by an editable installation. Thus no correct future write implementation can produce the asserted fs call through this entry.
- **Minimal correction:** explicitly separate direct production tool-execute checkpoint evidence from real Layer-06 integration evidence. Preserve the tool's register-before-check semantics and preserve certified preflight short-circuiting. Pin the actual entry/abort timing for each case; full-pipeline pre-aborted cases require zero tool fs calls. To test an aborted call waiting on the mutation lock through Layer 06, abort after it has survived preflight and reached the real queue, with a discriminating gate. Do not change Layer 06 or have the runner suppress/retime its signal invisibly to manufacture the existing expected trace.

### L13-WP132-R005 — non-object raw arguments cannot enter the mandated Rust pipeline

- **Taxonomy/severity:** `CONTRACT_ASSURANCE_DEFECT`, blocking.
- **Affected:** schema `case.arguments` (any JSON), real Layer-06-only runner mandate, and `builtin-edit-corpus-prepare.yaml::prepare-not-an-object`.
- **Pi reproduction:** `prepareEditArguments` defensively returns a non-object unchanged; the authority's standalone prepare/schema probe legitimately records a schema-invalid verdict. That does not establish that every Minion ToolCall boundary can carry such a value.
- **Concrete contradiction:** the case supplies `arguments: "just a string"` and requires **prepared** arguments to fail the tool schema through Layer 06. Certified Rust `llm/vocabulary.rs::ToolCall.arguments` and its constructor accept `BTreeMap<String, Value>`; `tools/execution.rs::arguments_value` always constructs `Value::Object` before `prepare_arguments`. There is no public full-pipeline path passing that string into preparation. Python's dataclass also annotates arguments as a dict; runtime permissiveness cannot be the cross-language contract authority.
- **Minimal correction:** disclose and classify this entry-domain constraint. Keep defensive preparation behavior evidenced through the real public prepare callback/helper where applicable, separately from the object-valued ToolCall integration surface; or use an explicitly specified pre-ToolCall rejection witness if that is the intended observation. Do not fabricate a Layer-06 schema result in the runner, wrap the string in a made-up object, or silently widen a certified lower-layer vocabulary. Any genuine lower-layer widening needs its own approved delta process.
