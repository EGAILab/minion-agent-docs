== A real build hazard the proof caught ==

The first run failed at PyICU import with `undefined symbol _ZTIN6icu_7811ReplaceableE`. Cause:
the base image ships Debian's libicu-dev 72.1, and PyICU's link line placed -L/usr/lib/x86_64-
linux-gnu BEFORE -L/opt/icu-78.3/lib, so -licui18n silently resolved to the system ICU 72 dev
library; no icu_78 symbol resolved and --as-needed dropped the NEEDED entries. This is exactly the
"whatever the OS provides" skew Correction 3b warns about. Fix, inside the disposable container
only: purge libicu-dev, hard-fail if any unversioned libicu*.so or /usr/include/unicode remains,
and hard-fail unless every ICU library either engine resolves (ldd) lives under /opt/icu-78.3/lib.
Final run: PyICU NEEDED libicui18n.so.78 + libicuuc.so.78; both engines resolve libicuuc,
libicui18n, libicudata .so.78 from /opt/icu-78.3/lib (results/run.log).

== Corpus and method ==

Corpus: the 24-name witness set from assurance/layers/13-wp131-ce-l13-wp131-01-characterization.md
Part 6 (lines 500-507), codepoints re-extracted from that file, including e+U+0301 and U+00E9 as
distinct entries (harness/corpus.json).
Modes: (1) raw names; (2) names lower-cased ONCE by the harness and stored in corpus.json, read
verbatim by both engines -- mirrors Pi's a.toLowerCase().localeCompare(b.toLowerCase()) shape
without letting either language's own case mapping differ.
Comparison: every ordered pair (24 x 24 = 576) per mode, plus a stable sort from enumeration
order, compared by harness/compare.py (plain JSON, no ICU).
