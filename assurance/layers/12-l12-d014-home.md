# L12-D014: where `~` gets its home directory (scoping 1)

Status: **SCOPING, PROPOSED for independent scoping review.** Coordination: `minion-agent#236`. Delta of `EXEC-002`/`EXEC-005`. Class: governing, CP-6 (WORKFLOW 11.8.11(c)). No code or shared case changes in this candidate.

## 1. Source

The `#229` CE-L12D012-02 native-read inventory (issuecomment-6183499893 §6) classified home expansion as a separate, pre-existing parity question. It was accepted as out of that checkpoint (issuecomment-6183538250). Spec §3.2 says only "a bare `~` resolves to the home directory", without naming the source of that directory, its mapping, or its failure. No canonical case covers it.

## 2. Authority (pinned Pi `b7bb00b9`, Node v22.15.1)

`resolvePath` (`nodejs.ts:51-65`) has three home cases:
- `~` becomes `homedir()`;
- `~/…` becomes `join(homedir(), rest)`;
- on win32, `~\…` does the same.

It then reaches the ordinary absolute-or-relative decision. `homedir()` is `os.homedir()`, a checked binding over libuv's `uv_os_homedir`, decoded by `String::NewFromUtf8` (replacement decoding). It is called **outside** any `try`, so a failure throws out of `resolvePath` and rejects the `ctx.fs` operation. The effective spawn cwd of `ctx.shell`/`ctx.subprocess` throws the same way.

| | win32 (`deps/uv/src/win/util.c`) | POSIX (`deps/uv/src/unix/core.c`) |
|---|---|---|
| First source | `USERPROFILE` (`uv_os_getenv`: `GetEnvironmentVariableW`, then WTF-8) | `HOME` (`getenv`) |
| When set | used, **unless** its UTF-8 length is under 3 bytes. Then it is `UV_ENOENT`, a **throw**, with no fallback | used as-is, including the empty string |
| When unset | `uv_os_get_passwd`, which is `GetUserProfileDirectoryW` of the process token (the account profile) | `uv_os_get_passwd`, which is `getpwuid_r`. A uid with no entry **throws** |
| Never read | `HOME`, `HOMEDRIVE`, `HOMEPATH` | `USERPROFILE` |
| Buffer | Node passes a fixed `PATH_MAX` buffer. A longer value is `UV_ENOBUFS`, a **throw** | same |

## 4. Classified differences

| ID | Condition | Pinned Pi (Node) | Merged Python | Rust (main) |
|---|---|---|---|---|
| H1 | win32 `HOME` set or empty, any `USERPROFILE` | ignores `HOME` | ignores `HOME` (matches) | **uses `HOME` first** |
| H2 | win32 `USERPROFILE` unset | account profile (`C:\Users\<user>`) | `~` left literal (`C:\x\~`), or `HOMEDRIVE`+`HOMEPATH` | `HOME`, else `~` literal |
| H3 | win32 `USERPROFILE` set but under 3 UTF-8 bytes (`""`, `C:`) | **throws** `ERR_SYSTEM_ERROR` (observed); the source says `UV_ENOENT` | uses the value | uses the value (or `HOME`) |
| H4 | value longer than Node's buffer (win32 `USERPROFILE` of 300 units; Linux `HOME` of 5000 bytes) | **throws** `ERR_SYSTEM_ERROR` (observed); the source says `UV_ENOBUFS` | uses the value | uses the value |
| H5 | POSIX `HOME` unset | `getpwuid` (`/root`). A uid with no entry **throws** | `pwd` (matches); no entry gives `~` literal | `USERPROFILE`, else `~` literal |
| H6 | POSIX `HOME` empty | `""`, so `~` resolves to the provider cwd | `/` (`rstrip` then `or sep`) | matches Node |
| H7 | lone surrogate (win32) or invalid UTF-8 (POSIX) | win32: 3 U+FFFD per lone unit; POSIX: maximal-subpart U+FFFD | the raw lone surrogate (win32), or `surrogateescape` (`\udcff`) | win32: 1 U+FFFD (matches POSIX) |
| H8 | win32 `\\?\` value | kept | kept (matches) | **stripped** (`from_native`) |

**Routed out.** Python's POSIX `//h/px` home keeps its leading `//`, where Node gives `/h/px`. That is a general posixpath normalization difference and is not home-specific. It is reported to `#235` as M4 (that candidate's `linux/baseline/rooted-02`).

## 5. Open points for the scoping review

1. **Throw mapping.** Pi throws in H3, H4 and the H5 no-entry case. The ports would map these as L12-D012 maps a native process-cwd read failure: the spec §2 typed error, never a guessed home. I propose the same statement here.
2. **Buffer bound.** The exact win32 limit (Node's `PATH_MAX` there) is not yet pinned. I propose a boundary characterization (lengths around the limit, in UTF-8 bytes) before the contract states it.
3. **H5 no-entry for Python.** `pwd.getpwuid` raises `KeyError`, which `expanduser` turns into "`~` unchanged". The contract would require the typed error instead.
4. **Canonical cases.** I propose host cases in crafted-environment children on both platforms, Node-generated, for H1–H8. The account-profile and `getpwuid` branches compare against the child's own observed source rather than a host constant: on win32 the token profile directory; on POSIX the `pwd` entry for the child's uid.
5. **Inventory.** `minion_agent/auth/context.py` also expands `~` (Pi's auth path rule, a different seam). It is listed here and not in scope.
