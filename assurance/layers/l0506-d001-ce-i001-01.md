# CE-L0506-D001-I001-01: pydantic declared-type characterization (convergence episode)

- **Coordination:** `minion-agent#88`, state CONTRACT_CONVERGENCE.
- **Trigger:** A. `L0506-D001-I001` survived two independent reviews: `#200` comment `5913924339`, then `#90` comment `5918098742`.
- **Purpose:** characterize the bounded pydantic declared-type / composed-branch surface, and agree a checkpoint **before** another patch.

No code change accompanies this record.

## Root cause of the surviving defect

Both earlier mechanisms judged a union **after pydantic had already chosen a branch**:
- the JSON-schema filter;
- the declared-type walk over the *validated* instance, which picks the first union member whose outer Python class matches.

A validated value no longer carries the alternatives. For example, with `list[float] | list[Any]`, `[inf]` is just a list, so the walk tries `list[float]` first and rejects. Pi's `anyOf` accepts it, because some alternative accepts the complete value. The same flaw hits `Inner | dict[str, Any]`: pydantic returns an `Inner` instance, and the `dict` alternative is lost.

## Candidate mechanisms, characterized

1. **Force `allow_inf_nan=False` into the model's pydantic-core schema.** Rejected by evidence. pydantic-core honors the flag on `float`/`nullable` nodes but ignores it inside a `model` node, whatever the node's `config` or `ref` (pydantic 2.13.4 / pydantic-core 2.46.4).
2. **Walk the validated instance.** Rejected. It is branch-lossy, as above.
3. **Proposed: a finite variant of the model, validated by pydantic itself.**
   - The variant has the same field names, `FieldInfo` (aliases, defaults), config, validators and base.
   - Every `float` occurrence in a field annotation is rewritten, recursively, to `Annotated[float, pydantic.AllowInfNan(False)]`. The rewrite goes through unions/`Optional`, `Annotated` (metadata kept), `list`/`tuple`/`set`/`dict` arguments, nested `BaseModel` classes (built as finite variants too), `TypedDict`s and dataclasses.
   - Validation of the prepared arguments is otherwise unchanged. The original model's validation result is returned, so pydantic coercion is unchanged.
   - The finite variant then validates the same prepared arguments. Only a failure of the variant rejects the call, as Layer 06's argument-validation error.

   pydantic's own union semantics (smart mode, every branch tried against the complete value) then decide: a non-finite value is accepted exactly when some finite-only alternative accepts it. That is Pi's `anyOf` behavior. The mechanism does no first-match, sweep or outer-class guessing.

## Characterization matrix (`data/l0506-d001-ce-i001-01/`)

**Authority.** For each row, a one-field model is built from the annotation. Its **own generated JSON schema** runs through pinned Pi's unmodified `validateToolArguments` (`typebox` 1.3.7, SRI-checked, `node:22.15.1-alpine`).

**Rule side.** The proposed finite-variant rule runs over the same prepared value. In this matrix the finite annotations are **hand-written** to mirror the proposed rewrite (`matrix.py` `ROWS`), because the automatic rewrite does not exist yet. The eventual patch must reproduce these 100 verdicts through the real rewrite.

**Dimensions.**
- 20 rows × 5 values = **100 cells**.
- Rows: scalar; nullable in both orders; numeric-or-string in both orders; numeric-or-`Any` in both orders; numeric-or-`object`; list, list-or-list-`Any` in both orders; dict, dict-or-dict-`Any` in both orders; model, model-or-dict-`Any` in both orders; TypedDict; dataclass; `Any`.
- Values: +Infinity, -Infinity, NaN, -0, 1e308.

**Result: 94/100 cells agree with pinned Pi.**

| Row | ±Inf, NaN (Pi = rule) | -0, 1e308 |
|---|---|---|
| scalar, nullable (both orders), list, dict, model, TypedDict, dataclass | **reject** | accept |
| numeric-or-`Any` / `Any`-or-numeric / numeric-or-`object`, list-or-list-`Any` (both orders), dict-or-dict-`Any` (both orders), model-or-dict-`Any` (both orders), `Any` | **accept** | accept |

This covers both branch orders, numeric-only against unconstrained alternatives, scalars, containers, nested model, TypedDict and dataclass, `Any`/`object` unions, a nullable number that is truly rejected, retained `-0` and large finite values.

**The 6 differing cells (proposed classification: the existing certified coercion divergence, not this delta).**
- **The cells:** `float | str` and `str | float` × {+Infinity, -Infinity, NaN}. Pi *accepts* these by **coercing** the number to a string (`coerceWithUnionSchema`: `Infinity` → `"Infinity"`). The rule rejects.
- **The coercion is general.** Pi coerces a *finite* number in a `{type: string}` field the same way (`5` → `"5"`). Minion already rejects that today, per `coerce_probe.mjs`.
- **Why it's the existing divergence.** Certified Layer 06 (`TOOL-003`; `spec/tools.md` Layer 06 validation) states that neither validation path reproduces Pi's TypeBox coercion/conversion. That is a disclosed, intentional divergence, predating and outside this numeric delta.
- **Not a finite-rule question.** Pi's result there is a *string*, not a runtime number, so no prepared runtime number is involved.
- **Consistency with the certified JSON-Schema path.** For `{anyOf: [number, string]}` it rejects the same way: it does not coerce, and its `number` is finite-only.
- **Proposed.** Record these cells as falling under that existing disclosure, not a new divergence. **If the challenge judges this a new divergence created by the delta, it goes to the Owner.** Changing Minion to coerce is outside this delta's authorization.

## Positive and negative controls for the eventual patch

- **Positive:** all 94 agreeing cells, as real-pipeline witnesses. Among them are the two review probes (`float | None`; a model with an opaque field) and Codex's pair (`list[float] | list[Any]` / `list[Any] | list[float]`), plus `Inner | dict[str, Any]` in both orders.
- **Negative controls:**
  - a first-match/outer-class walker, which Codex's pair kills;
  - a whole-model non-finite sweep, which kills the `Any` and dict-`Any` rows;
  - JSON-schema-only filtering, which kills nullable and opaque-field;
  - no finite check at all, which kills scalar, list, model, TypedDict and dataclass;
  - `-0` collapse, which kills the `-0` column.
- Pydantic coercion stays unchanged: the returned value is the original model's.
