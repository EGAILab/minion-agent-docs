## Design notes
**Settlement.**
- The run waits for the process's exit, then for EOF on both pipes or 100 ms without further data. Each chunk re-arms that window.
- At settlement it calls `ReadableStream.close()` on stdout and stderr, never `terminate()`.
  - A background job (`cmd &`) survives the command, and its next write meets a closed reader.
  - Late output is not part of the result. This is Pi's `child.stdout?.destroy(); child.stderr?.destroy()`.

**Lookup.**
- Read pumps run concurrently against one 1 MiB budget over both pipes; the crossing chunk is kept.
- The timer is 5000 ms.
- Collection ends at exit plus EOF on both pipes, with no grace period.
- An unexited lookup is interrupted through `terminate()` (`DIV-001`). An exited lookup keeps its status (`C002`).
- The streams are closed when collection ends.

**Decoding.**
- One CPython incremental `utf-8-sig` decoder with `errors="replace"` runs over the merged chunks of both pipes. This is WHATWG UTF-8 with exactly one leading BOM stripped, even when the BOM is split across chunks.
- The rolling tail and the line-boundary flag follow Pi's `OutputAccumulator`.
- `truncated`, `truncatedBy` and the totals come from the whole stream.

**Full-output file.**
- It is created through `ctx.fs` when the stream first needs it, back-filled with every earlier raw chunk, then appended.
- It holds the raw bytes, never decoded text.
- If the file cannot be written, the run ends (Minion-defined).

**Precheck order** follows Pi's `exec`: timeout validation, then abort, then shell selection, then cwd. The cwd check is `probe_dir_entry` on POSIX and `file_info` on Windows (`CE-WP133-01`).

**Classification:** the signal first, then the timeout, then the exit code. `"(no output)"` is the empty text, including after a non-zero exit (`WP133-CON-R001`).

**Timer:** `max(1, trunc(ms))` (`WP133-CON-R003`).

**Session environment (Owner Q1).** Variables are removed by exact spelling; a case variant survives. They are then re-injected from the call's `ToolExecutionContext`. Absent fields are never injected as `"none"` or `""`.

**Command projection (`WP133-AUD-R001`).** The scalar form is computed before either transport: an unpaired surrogate becomes U+FFFD.

## Remediation 1 (after Codex implementation review 1)

Review 1 (`minion-agent#146` comment `5976399232`) at `65febdbe` / `9699a417` returned CHANGES REQUIRED with two findings. Both were accepted as stated.

**`WP133-I001`: an incomplete leading BOM at EOF was dropped** (PI_PARITY_DEFECT).
- CPython's incremental `utf-8-sig` decoder silently discards an incomplete initial `EF` or `EF BB` on its final flush. Pi's `TextDecoder` emits U+FFFD (3 decoded bytes).
- **Fix:** decode with the plain incremental `utf-8` decoder in replacement mode, and strip one U+FEFF only when it is the stream's first decoded character. Only a complete leading `EF BB BF` produces that character.
- **Witnesses** (accumulator): `EF`, `EF BB` and a split `EF`|`BB` give U+FFFD and 3 bytes. A complete or split BOM still gives empty output, and a lone `E2` still gives U+FFFD.
- **Witness** (public tool): `printf '\357'` and `printf '\357\273'` produce U+FFFD, not `(no output)`.
- The pinned BOM rows stay green.

**`WP133-I002`: settlement cancelled an in-flight full-output write** (PI_PARITY_DEFECT).
- Each pump both read and persisted. Cancelling it at the end of the grace cancelled an accepted write whose bytes had already left the backlog.
- **Fix:** intake (read, accumulate, enqueue) is synchronous after the read, so cancelling a pump can only cancel a pending read. One ordered writer persists the accepted chunks, and settlement joins it before finishing. This matches Pi's `finishOutput()` awaiting `closeTempFile()`.
- Cancelling the tool call propagates into the awaited writer, so no write outlives the call.
- **Witnesses**, each with an event-gated, conforming `append_file`:
  - **success:** the run does not return while the write is held, and then every one of the 51,201 bytes is in the file;
  - **delayed error:** the file-error classification is kept;
  - **cancelled call:** no write completes after the call is gone.

**Controls added:**
- `bom-prefix-dropped-at-eof` (the I001 regression);
- `settlement-cancels-persistence` and `persist-inline-in-pump` (the I002 regression);
- `per-chunk-bom-strip`, now injectable and no longer structural;
- the decoder fault anchors updated to match the new decoder.

The control runner now refuses to count a collection or setup error as a kill. A mis-indented fault had briefly been credited that way.

## Remediation 2 (after Codex targeted closure 1)

Targeted closure 1 (`.tmp/wp133-review/CLOSURE1.md`) provisionally closed WP133-I001 and WP133-I002, and found **`WP133-I003`** (PI_PARITY_DEFECT). Remediation 1 had moved the writer join inside `settle()`, so the timeout timer, cancelled only after `settle()` returned, stayed active during full-output finalization. Pi clears the timer and removes its abort listener in `exec`'s `finally`, before `finishOutput()` awaits `closeTempFile()`.

**Fix.** The run now has two phases.
- `_Run.settle()` ends the command: exit, grace, and the read ends released.
- `run_command` then disposes of the timer and background tasks, and records `aborted` and `timed_out` at that point.
- Only after that does `finish_output()` join the accepted-write writer and flush.
- If the call is cancelled with a write still in flight, the writer is discarded.

**Witnesses** (each uses a gated, conforming `append_file`):
- the 0.3 s timeout passes during finalization, the result is success, and nothing is terminated;
- an abort during finalization does not change the classification;
- a call cancelled mid-run with a write in flight writes nothing afterwards.

**Controls added:** `timer-active-through-finalization`, `abort-classified-after-finalization` and `writer-orphaned-on-cancel`. The timeout-first and join anchors follow the new code.

The branch also merged main `62caa152`, which brought the Rust EXEC-012 changes and the manifest pointer.
