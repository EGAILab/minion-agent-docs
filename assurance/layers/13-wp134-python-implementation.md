## Design notes
**Engine resolution (`TOOL-038`, `DIV-003`).**
- A tool takes an engine source: the certified `EngineStore`, or an explicit `EngineOverride` (uncertified; an argv prefix used as given).
- `EngineStore.resolve` makes three checks, in order. If the platform has no pin, the result is the "not available on this platform" text. If the binary at the fixed name fails its SHA-256 (verified on every call, off the event loop), the result is the "not provisioned" text. Otherwise it returns the binary.
- It never consults `PATH` and never downloads.
- A store is usable only in the local execution world. Elsewhere the result is "not available", naming the world.
- `provision_search_engines(store, source=None)` works as follows:
  - it fetches the official URL, or reads a local directory of official artifacts;
  - it verifies the artifact SHA-256 before extraction and the binary SHA-256 after;
  - it installs through a temporary file in the store and an `os.replace` to the fixed name;
  - it is idempotent, returning `installed` or `present` per engine.

**`find` (`TOOL-036`).**
- The order is the contract's:
  1. abort pre-check;
  2. path pipeline, then `absolute_path`;
  3. engine;
  4. abort check;
  5. `.git` walk (`file_info` on Windows, `probe_dir_entry` on POSIX, `WP134-CON-R001`);
  6. `--no-require-git` outside a repository;
  7. `--max-results` via `Number::toString`;
  8. full-path handling.
- `execute` races the work against the signal (`race_abort`): an abort settles `Operation aborted` at once, and the work's watcher terminates the process.
- Stdout runs through the readline splitter. The empty test is on the raw lines joined, before any trim; each line then has one `\r` stripped and is `js_trim`med.
- Relativization uses the platform's Node path functions. On win32 the comparison is case-insensitive, and a path on another drive keeps the target.

**`DIV-002` rewrite.**
- On Windows every `/` becomes `[/\\]` (Pi), except that a `/**/` outside braces becomes `{[/\\],[/\\]**[/\\]}`, which also matches zero directories.
- An escaped character and a character class are never part of a `/**/` component, but their `/` still takes Pi's rewrite. Outside real `/**/` components the text is exactly Pi's `replaceAll`, so every other construct keeps Pi's meaning on the pinned fd (spec "Windows full-path scope").

**`grep` (`TOOL-037`).**
- The order is: abort pre-check, engine, path, then `probe_dir_entry` (an error gives `Path not found`).
- `context` is used only when truthy and `> 0`. The limit is `Math.max(1, limit ?? 100)`.
- The abort watcher is registered after spawn. An abort that happens before then is not observed, as in Pi.
- Every `match` event counts. It is collected only with `path.text` truthy and a numeric `line_number`.
- At the limit the engine is stopped once ("killed for limit"), which suppresses the exit-code error.
- Context blocks come from a cached re-read: `read_binary_file`, UTF-8 decode keeping the BOM, CRLF/CR to LF. Fractional positions read as `""`, and overlapping windows are not merged.
- `truncate_line` counts UTF-16 units and can split a surrogate pair.

**Shared.**
- Engine argv takes its scalar form before spawn (an unpaired surrogate becomes U+FFFD), per the WP-13.3 projection rule (`WP133-AUD-R001`).
- Spawn uses `inherit_env`. Spawn failure gives `Failed to run fd|ripgrep: <Layer-12 message>`.
- Both pipes are read to EOF and closed after exit (spec/execution.md §16).
- A stop requested by `on_line` keeps a reference to its termination task and awaits it before `wait()`.

## Findings during implementation (self-found, before review)
1. **Escaped `/` in the Windows rewrite.**
   - The first draft passed an escaped character through untouched, so `\/` stayed `\/`. Pi's `replaceAll` gives `\[/\\]`.
   - The spec requires every non-`**/` construct to keep Pi's meaning, so the escape now takes Pi's rewrite.
   - The witness now checks, for six patterns without a real `/**/` component, that the output equals Pi's `replaceAll`.
2. **Control design, following `.git` probe.**
   - The first mutant swapped `file_info` for `probe_dir_entry` and survived. On Windows neither follows: both return Ok for a dangling junction.
   - The realistic following probe is `canonical_path`, which fails for a dangling junction. With it, the control is killed by witness 7, the junction scenario.
   - The control table records this mutant.
3. **Controls without an intended witness.**
   - `PATH` fallback, download from a tool call, a non-atomic install, trimming before the empty test, and deduplication had no witness that would discriminate them deterministically. A pass would have depended on the host: no `fd` on `PATH`, no network, the cleanup handler hiding a direct write.
   - Dedicated witnesses were added under workflow §9.7:
     - `test_a_tool_call_never_downloads_or_uses_path` plants `fd`/`rg` on `PATH` and makes any fetch raise;
     - `test_the_fixed_name_appears_only_by_the_atomic_rename`;
     - `test_find_tests_emptiness_before_trimming`;
     - `test_find_keeps_entries_that_format_identically`.
4. **Unreferenced stop task** (ruff `RUF006`): the stop-on-limit termination task is now kept and awaited.

**Linux recipe (§9.8).**
- Container: `docker run python:3.13`, with these mounts:
  - the worktree, read-only;
  - the engine artifacts at `/artifacts`;
  - the pinned ICU 78.3 Linux build volume at `/icu`.
- Strip CR from `*.sh`, then `eval "$(bash scripts/pinned-icu/build.sh /icu --env)"`.
- `pip install ada-url==1.15.3 url-py wasmtime==49.0.0 pydantic pyyaml jsonschema httpx pytest pytest-asyncio pytest-cov hypothesis PyICU==2.16.2`.
- Run `PYTHONPATH=src python -m pytest -c /dev/null --rootdir=<pkg> -o asyncio_mode=auto -W error::pytest.PytestUnraisableExceptionWarning`, with `MINION_SEARCH_ENGINE_ARTIFACTS=/artifacts`.
- For the controls, also set `E5_BARE_PYTEST=1`.

**Engine provisioning for the gates.**
- The conformance suite provisions a temporary store from `MINION_SEARCH_ENGINE_ARTIFACTS`, a directory of the official release artifacts under their official names.
- Provisioning verifies both SHA-256s, so the directory is not trusted.
- Without the variable, the conformance cases skip: the guard is the fixture's explicit skip. A gate run must set it.
