## OPEN FINDINGS

- `L0506D005-C003`: the canonical runner's fixture decoding is not total over valid `JSON.parse` number literals. A JSON integer literal beyond binary64's range (±401 digits) raises `OverflowError` in `raw_arguments_runner.number`, where pinned Pi's `JSON.parse` yields ±Infinity.

## ROOT-CAUSE SURFACE

Turning a raw JSON text's number **literal** into the runtime value the pipeline receives (the fixture's `JSON.parse`).
- The certified `raw_arguments_runner.number` decodes a **preflighted, finite** token. Its precondition is a token naming a finite binary64 value, which the raw-arguments schema enforces.
- The `arg_isolation` `raw_text` field carries any valid JSON, so that precondition was not met for an overflowing integer literal.
- Observation (`prepared_runtime_runner.render`) already represents ±Infinity, so it is not part of the surface.

## PI SYMBOLS / TESTS AUDITED

- Pinned Pi's raw arguments are `JSON.parse` values (`L0206-D002`). The `arg_isolation` oracle (`gen/pi_oracle.mjs`) parses `raw_text` with Node v22.15.1 `JSON.parse`: correctly rounded binary64, with overflow giving ±Infinity for both integer and exponent spellings.
- Codex's review-2 probe (`.tmp/codex-scratch/l0506d005/review2_number_probe.py`, with `overflow-{cases,pi}.json`) observed through the real pinned-Pi path: a positive 401-digit integer gives `+Infinity`, the negative one gives `-Infinity`, and `1e400` gives `+Infinity`.

## OBSERVABLE RULES

1. A raw number literal is the correctly rounded binary64 value of its spelling, as `JSON.parse` gives it.
2. A literal whose correct rounding overflows is **±Infinity**, whether it is spelled as an integer or with an exponent. The boundary is 2^1024 − 2^970: that integer, and every larger one, rounds (ties-to-even) to Infinity; 2^1024 − 2^970 − 1 rounds to the largest finite double.
3. `-0` stays negative zero. A finite integral literal is its binary64 value's **exact** integer, never the spelled digits. Exponent and decimal spellings decode to the same binary64 values.
4. Observation stays strict and total. An integer that is not exactly binary64 can never match a token (`{non_binary64_int}`).
