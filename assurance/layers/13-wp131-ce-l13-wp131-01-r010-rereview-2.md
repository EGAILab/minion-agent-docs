## Blocking finding

### L13-WP131-R010-D — later content-read failures are still collapsed to `is_directory`

**Classification:** `CONTRACT_ASSURANCE_DEFECT`

Revision 3 adds a binding general rule that `not_supported` is reachable at every raw/hybrid site
when the provider cannot supply the operation. It then contradicts that rule in this row:

```text
read: path is a directory (access succeeds, later content-read step fails)
    reachable code: is_directory (exactly one)
```

The actual Minion implementation boundary is provider-neutral Layer 12, not Node's local
`readFile` alone. Its typed operations are:

```text
read_text_file(path, signal?)   -> Result[str, FsError]
read_binary_file(path, signal?) -> Result[bytes, FsError]
```

Neither the certified interface nor `FsErrorCode` restricts those calls to `is_directory`. A
provider may successfully support the earlier access/existence step and then return
`not_supported` from content reading. The same later call can also report `not_found` after a
TOCTOU removal, `permission_denied`, `not_directory`, `invalid`, or `unknown`. Only the specific
subcase “the addressed path is a directory” maps exactly to `is_directory`; the operation site as
a whole does not.

Minimal discriminating witness:

```text
setup
    provider supports the pre-read access/existence check
    provider returns Err(FsError(not_supported, "binary reads unavailable"))
    from read_binary_file(path)

candidate table
    later content-read failure -> is_directory exactly

actual certified seam
    later content-read failure -> not_supported

distinction
    R010-B has no complete mapping/template-selection rule for the observable tool failure;
    R010-A likewise lacks an explicit row tying this provider message to the later read site
```

This is the same root finding, not a new semantic surface: revision 3 correctly repaired
`list_dir_raw` but did not apply its own provider-capability rule to the final remaining raw read
site.

**Minimal correction:** split the row into:

1. the specific directory witness (`read_*_file -> is_directory`); and
2. the general later `read_text_file`/`read_binary_file` failure site with the full reachable
   provider-neutral taxonomy, including `not_supported`.

Audit the other actual Layer-12 operations consumed by `read` once, so the “complete mapping” claim
is based on Minion's real operation seams rather than only Node-local errno examples. No Layer-12
change is required.
