## 2. Implementation

`execution/path_resolve.rs` is the lexical, UTF-16 Node resolver. It owns root
recognition, right-to-left argument selection, device comparison, select-then-check,
and dot-component normalization. A colon in an ordinary component does not grant
it drive-prefix status. It does not interpret components with `PathBuf::push`.

Both the lossless filesystem resolver and the scalar shell/subprocess resolver
delegate to that authority. File URL conversion keeps its certified USVString
boundary and malformed-URL fallback. Home expansion follows Pi's platform rule
(`~\\` is a home prefix on Windows only).

The private `resolve_logical` entry point carries both arguments as `FsPath`;
the existing OS-path convenience entry point delegates to it. The new raw codec
is confined to logical cwd transport and selected native reads. The established
native filesystem-result/display mapping remains unchanged. This avoids a
collateral change to other native filesystem results while preparing the seam
that #228's separate lossless carrier can reuse. Node's upstream path notice is
included in `THIRD-PARTY-NOTICES.md`.

**Native-read failures.** Self-review found that the initial candidate unwrapped
`std::env::current_dir`. The corrected path is fallible: the native-read view and
the lexical core preserve an I/O error, and the filesystem, shell and subprocess
callers use their existing error-domain mappings. They do not manufacture a root
or cwd after an error. `exists` remains derived from `file_info`. An unresolved
native-cwd read has no invented addressed path. This implements the existing
typed-operational-error rule; it is not a new Node-literal message rule or a
change to the 80 canonical expectations. The earlier feasibility note that
resolution "never errors" describes malformed-URL fallback too broadly when
applied to a fallible host-state read; the Rust fault witnesses cover that read.

Native selection is lazy: `view(inherited entry) || view(process cwd)`. The
selected value's third character is its **third UTF-16 code unit**, not its third
Unicode scalar. Each unpaired native surrogate becomes three U+FFFD units under
the §15 view; valid pairs and a BOM survive. Provider cwd and caller path remain
logical UTF-16 strings. The separate projection immediately before an OS call
still replaces an unpaired surrogate once, not three times.

The existing pinned Node/Unicode-16 lowercase implementation and table moved
from `tools/builtin/search_node_lower.{rs,json}` to
`execution/node_lower.{rs,json}` and are shared by search and resolution. The
table bytes are unchanged; there is no host-Unicode substitution.
